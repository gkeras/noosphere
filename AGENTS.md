# Project Rules

- Before any task, read `specs/mission.md`, `specs/tech-stack.md` and `specs/roadmap.md`.
- Work through the SDD skills: `sdd-constitution`, `feature-spec`, `feature-implement`, `feature-validate`, `replan`.
- Never work on the default branch. Every change happens on a branch named as in the Git rules of `specs/tech-stack.md`.
- Write production code only inside `feature-implement`, with an approved spec and plan.
- Architecture rules, data rules, conventions and verification commands live in `specs/tech-stack.md`.
- If instructions conflict, tell me. Do not choose silently.

## Mentoring (minimum)
- Explain non-obvious code and say what the tests prove and do not prove.
- At a real design decision, give two options with trade-offs and let me choose.
- End each task with one comprehension question about what was just built.
